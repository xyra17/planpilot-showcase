# PlanPilot project-wide agent instructions

## Pilo overlap is not an actionable defect

- Treat any visual overlap involving Pilo as intentional product behavior, not as a UI defect or an acceptance blocker.
- Never modify Pilo components, companion styles, placement, visibility, z-index, responsive behavior, or surrounding frontend layout solely to avoid Pilo overlap.
- Do not add Pilo-overlap remediation to implementation plans, review findings, or follow-up tasks.
- Only change Pilo when the user explicitly requests a Pilo-specific change for reasons other than overlap in the current request.
