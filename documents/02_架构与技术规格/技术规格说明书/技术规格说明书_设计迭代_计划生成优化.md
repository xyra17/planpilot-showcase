# 技术规格说明书 — 设计迭代：计划生成优化

> **类型**：设计缺陷分析 + 迭代方案  
> **日期**：2026-07-23  
> **涉及模块**：Agent 引擎（macro-plan）、前端计划生成流程（PlanModeSelector）

---

## 一、问题本质与缺陷分析

### 结构性缺陷

当前计划生成流程存在**上下文信息严重不足**的设计缺陷。LLM 生成计划时，仅能依赖：

- 结构化字段：标题、截止日期、每日学时、当前水平
- 知识库片段：前 10 条 × 前 300 字的截断内容

无法获得：

1. **用户真实意图**：本次学习有哪些具体期望？优先级是什么？已有哪些基础？
2. **知识库全貌**：库内有哪些文档？各自多长？内容侧重点是什么？
3. **目标类型差异**：备考类（有考纲约束）与技能类（开放探索）的计划逻辑根本不同

### 典型问题示例

**示例一：知识库存在但计划无视内容**

> 用户上传了《Python 从入门到实践》（400 页）和《数据分析实战》（250 页），目标是"学会用 Python 做数据分析"。  
> 当前结果：AI 生成了通用 Python 教程路径，任务内容与上传书籍章节完全不对应，知识库形同虚设。

**示例二：备考目标缺乏考纲结构**

> 用户目标是"考研英语备考"，知识库关联了真题集和词汇书。  
> 当前结果：AI 生成了"每天背单词 + 阅读练习"的循环计划，没有按考研英语模块（完型、阅读、翻译、写作）分阶段规划，也没有参考真题集的难度分布。

**示例三：用户基础信息被粗糙处理**

> 用户填写"当前水平：中级"，但这对 LLM 来说过于模糊，无法区分"已掌握基础语法但从未写过项目"还是"有工作经验但需要补算法"。用户没有渠道补充更精确的上下文。

### 根因分析

| 维度 | 当前问题 | 影响 |
|------|----------|------|
| 意图表达 | 用户无法在结构化字段之外补充上下文 | 计划通用化，针对性差 |
| KB 感知 | 仅取前 10 条 × 前 300 字 | AI 不知道库的全貌和内容比重 |
| 类型差异 | 所有目标类型使用同一 prompt 模板 | 备考类缺乏考纲结构，技能类缺乏项目导向 |
| 节奏控制 | 无法根据 KB 文档量自动估算学习节奏 | 计划节奏不匹配实际内容量 |

## 二、重设计方案

### 2.1 生成流程：1 步 → 2 步

**旧流程**：
```
[目标已创建] → 选择 KB 模式 → 直接生成
```

**新流程**：
```
[目标已创建] → 步骤一：选择 KB 模式 → 步骤二：收集学习意图 → 生成
```

**步骤二内容**：
- **KB 概览**（自动加载）：显示关联知识库的文档列表和估计字数，让用户确认 AI"看到"了什么
- **初始理解**（LLM 轻量调用）：AI 基于目标和 KB 概览自动生成初步理解，供用户确认或修正
- **预设选项**（按目标类型分组）：常见补充意图的快速选择
- **自由文本**（必填）：用户自由补充，直接注入规划 prompt

### 2.2 Prompt 策略矩阵

**更新（2026-07-23）**：矩阵从 4 行扩展至 10 行，覆盖全部 6 类目标 × 2 种 KB 状态。

| 目标类型 | KB 状态 | 策略 |
|----------|---------|------|
| exam / certification | 有 KB | 严格按 KB 文档章节结构划分阶段，覆盖率为首要指标；后期冲刺+复习 |
| exam / certification | 无 KB | 警告"无考纲资料"，按通用考试结构生成，建议补充材料 |
| skill | 有 KB | KB 作为主要教材，结合实战练习；理论学习后立即配套项目练习 |
| skill | 无 KB | 基于目标描述和通用知识，生成项目驱动型计划 |
| reading | 有 KB | 以 KB 文档为阅读材料；按章节逐步精读，每章做笔记/摘要，关注理解深度 |
| reading | 无 KB | 建议关联具体书籍到知识库；生成通用阅读节奏计划 |
| language | 有 KB | KB 作为语言学习材料；大量输入（听力+阅读）为主，词汇积累+语法打底 |
| language | 无 KB | 大量输入为主，词汇积累+语法打底，注重实际应用 |
| habit | 有 KB | KB 作为习惯养成指导；从最小行为开始逐步递增，固定时间地点 |
| habit | 无 KB | 从最小可执行行为开始，固定时间地点，先建立节奏再提升强度 |

### 2.3 按目标类型的预设意图选项

**备考 / 认证类**（exam, certification）：
- 优先覆盖高频考点和历年真题
- 按模块分阶段，每阶段结束有专项复习
- 后期重点冲刺和错题回顾
- 知识点理解优先于大量刷题

**技能类**（skill）：
- 理论学习后立即配套实战练习
- 以项目为驱动，边学边做
- 快速入门后深入某个细分方向
- 系统性全面学习，不跳过基础

### 2.4 pacing_mode 设计

- `"fixed"`（默认）：严格按 `daily_hours` 固定节奏，与原有行为一致
- `"auto"`：根据 KB 文档总字数估算阅读时长，自动调整学习节奏

**auto 估算逻辑**：
- 中文阅读速度参考：约 20000 字/小时（日常阅读）
- 总阅读时长 = KB 总字数 ÷ 20000
- 注入 prompt，让 AI 在分配任务时参考实际内容量而非仅凭时间

## 三、新 API 设计

### GET /api/v1/agent/plan-context/{goal_id}

用于步骤二加载阶段，在用户点击"下一步"时调用。

**返回格式**：
```json
{
  "kb_overview": [
    {
      "title": "Python从入门到实践",
      "char_count": 120000,
      "estimated_pages": 200
    }
  ],
  "initial_understanding": "你正在备考考研英语，知识库中包含真题集和词汇书..."
}
```

- 使用 smart model（短 prompt，max_tokens=200，快速返回）
- `initial_understanding` 让用户在生成前校正 AI 的认知偏差
- KB 为空或无关联时，`kb_overview` 为空列表，`initial_understanding` 基于目标信息生成

### POST /api/v1/agent/macro-plan/{goal_id}（更新）

新增请求参数：

```json
{
  "kb_mode": "kb_reference",
  "user_intent_supplement": "我已经学过基础语法，希望重点练习项目实战，跳过基础理论部分",
  "pacing_mode": "auto"
}
```

- `user_intent_supplement`：作为高优先级约束直接注入 prompt
- `pacing_mode`：决定是否将 KB 字数信息注入节奏估算
- KB 获取策略升级：取全部 items（不限 10 条），每条只取 title + len(content)，不截断 content 注入 prompt

## 五、前端组件实现细节

### PlanModeSelector 两步流程

**步骤一（KB 模式选择）**：

```tsx
const MODES = [
  { value: "kb_only",      label: "仅从知识库生成",   requiresKb: true  },
  { value: "kb_reference", label: "参考知识库生成",   requiresKb: true  },
  { value: "no_kb",        label: "不参考知识库",     requiresKb: false },
];
```

`requiresKb: true` 的选项在无知识库时显示为禁用态（opacity-40 + cursor-not-allowed）。

**步骤一 → 步骤二 过渡**：

点击模式卡片后立即调用 `GET /api/v1/agent/plan-context/{goalId}`，加载期间显示 Loader2 动画，加载完成后切换至步骤二界面。

**步骤二（意图收集）**：

1. **AI 初步理解卡片**：蓝色背景，展示 `initial_understanding`，让用户校正偏差
2. **知识库文档列表**：灰色背景，展示 `kb_overview`（标题 + 估算页数），仅有 KB 时显示
3. **预设选项**：2×2 网格，按 `goalType` 分支显示 4 个快速选择按钮，可多选
4. **补充说明文本框**：自由文本，placeholder 有引导示例
5. **自动估算节奏开关**：仅有 KB 时显示，有 KB 时默认开启（`pacing_mode="auto"`）
6. **开始生成按钮**：需至少填写预设选项或自由文本之一才可点击

**提交逻辑**：

```tsx
function handleConfirm() {
    const optionLines = Array.from(selectedOptions).map(o => `- ${o}`).join("\n");
    const combined = [optionLines, freeText.trim()].filter(Boolean).join("\n");
    onConfirm(selectedMode, combined, pacingMode);  // 传递给父组件
}
```

预设选项和自由文本拼接后作为 `user_intent_supplement` 传入 `macro-plan` API。

## 五、关键设计决策

- **LLM 理解是生成前校正的机会**：`plan-context` 的 `initial_understanding` 让用户在生成前知道 AI 是否理解了目标，减少"生成后才发现跑偏"的返工成本
- **自由文本必填但不限格式**：用户可以写"跳过第 1-3 章"，也可以写"重点是写作，其次是阅读"，LLM 自然处理
- **预设选项是提示而非约束**：选中的选项拼接到 `user_intent_supplement`，不改变 API 结构
- **KB 感知升级**：从"截断内容片段"改为"文档目录 + 字数"，AI 获得的是全局视野而非局部片段
