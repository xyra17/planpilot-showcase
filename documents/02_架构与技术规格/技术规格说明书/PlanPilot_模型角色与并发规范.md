# PlanPilot 模型角色与并发规范

**状态**：现行规范
**更新时间**：2026-08-22

PlanPilot 只定义三个生成角色和一个向量角色。业务代码按角色请求能力，不按供应商名称猜测用途。

| 角色 | 主模型 | 回退 | 典型任务 | 结果契约 | 并发上限 |
|---|---|---|---|---|---:|
| `interactive` | 本地 Qwen3.5-9B MLX 4bit | DeepSeek V4 Flash | 普通聊天、打卡回应、短解释、目标理解、输入提示、复习题、笔记辅助 | 简短中文自然语言，可流式返回 | 本地服务全局 1 |
| `structured` | DeepSeek V4 Flash | 本地 Qwen3.5-9B | 宏观计划、每日任务、验收出题、复杂行动规划、学习洞察叙事 | JSON 或业务 Schema 校验通过后才采用 | Flash 每应用进程 4 |
| `critical` | DeepSeek V4 Pro | 无静默降级 | 学习答案评分；未来的复杂重规划终审 | 高质量判断或显式失败 | Pro 每应用进程 1 |
| `embedding` | 本地 Qwen3-Embedding-0.6B | 关键词检索 | 文档向量化、知识库检索、任务资料匹配 | 1024 维向量 | 查询每应用进程 1；文档每批 32 段 |

## 选择规则

### 优先不调用模型

专用业务接口中的当前目标、任务列表、日期、进度、状态、统计、CRUD、权限判断和明确关键词意图由数据库与确定性代码直接产生。在自由对话入口中，这些事实可作为证据交给 `interactive` 组织语言，但模型不得重新计算或猜测。

### Interactive

仅用于用户正在等待的自然语言回应。主模型是本地 Qwen，原因是隐私、成本和热请求首字速度。请求报错、本地熔断或排队超过配置预算时才回退 Flash。回退是可用性保险，不负责结构化业务写入。

### Structured

所有影响计划、任务建议或 Agent 工具选择的生成都属于该角色。Flash 作为主模型；返回值必须经过 JSON、Pydantic 或业务约束校验。Flash 请求失败时可尝试本地 Qwen；两者都不满足契约则显式失败，不把残缺数据写入业务表。

### Critical

只用于需要高质量判断的低频任务。Pro 没有低等级自动回退；服务不可用时显示可重试错误，避免把普通模型结果伪装成最终审核。

### Embedding

Embedding 不属于生成模型，不参与 Local／Flash／Pro 路由。服务不可用时检索退化为关键词匹配，不调用 DeepSeek 生成模型伪造向量。

## 并发含义

- 本地 MLX 服务使用 `--prompt-concurrency 1 --decode-concurrency 1`，因此 API、Worker 即使同时请求，9B 模型也只执行一个生成任务。
- 应用层本地信号量也是 1；等待超过 `LOCAL_MODEL_QUEUE_TIMEOUT_SECONDS` 的交互请求可回退 Flash。
- Flash 上限 4、Pro 上限 1 是每个 Python 进程的应用保护值；云端供应商仍可能施加自己的账户级限流。
- Embedding 查询信号量为 1。文档索引把最多 32 个文本段合并为一次请求，提升吞吐而不并行挤占本机资源。

## 当前入口映射

| 入口 | 角色 |
|---|---|
| `/api/v1/agent/stream` 普通聊天、打卡、普通验收问题 | `interactive` |
| 目标理解、补充说明 placeholder、复习题、笔记辅助 | `interactive` |
| 宏观计划、每日任务、验收题及答案要点 | `structured` |
| 已知任务行动（新建、完成、删除、移动、逾期重排） | 零模型确定性计划 |
| 复杂行动 Planner、学习洞察叙事 | `structured` |
| 验收答案评分 | `critical` |
| 知识导入、检索、任务资料关联 | `embedding` |

## 运维检查

`GET /health/ai` 返回角色、主模型、回退和并发上限，同时检查本地生成与 Embedding 的配置模型 ID 是否和服务公布 ID 一致。响应不得包含 API Key。
