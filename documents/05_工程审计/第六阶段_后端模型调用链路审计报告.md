# 第六阶段：后端模型调用链路审计报告

**审计日期**：2026-07-26  
**审计范围**：本地 Qwen3.5 生成模型、DeepSeek Flash／Pro、Qwen3 Embedding、Agent、知识库、健康检查、超时重试、熔断、指标与相关测试。

## 1. 当前实际路由

| 用途 | 首选 | 回退 |
|---|---|---|
| 意图识别、聊天、目标理解、每日任务、宏观计划草案、复习题、普通验收出题、笔记辅助 | 本地 Qwen3.5-9B MLX | DeepSeek V4 Flash |
| 复杂重规划、学习答案最终评分 | DeepSeek V4 Pro | 无自动降级 |
| 文档向量化、知识库语义搜索 | 本地 Qwen3-Embedding-0.6B | 关键词检索 |

生成模型统一入口主要位于 `src/core/llm_router.py`，但任务与知识匹配仍残留一条绕过统一 Embedding 配置的旧调用。

## 2. 真实运行验证

### 2.1 服务与模型

- 本地生成服务 `localhost:8080/v1`：可访问；
- 本地 Embedding 服务 `localhost:1234/v1`：可访问；
- 应用实际 LangChain 路由最小生成：成功，约 0.81 秒；
- Qwen3 Embedding 最小调用：成功，约 0.51 秒，维度 1024；
- 遗留 DeepSeek Embedding 调用：稳定返回 HTTP 404。

本地生成模型 `.env` 中的模型名仍指向 Downloads 路径，而 `/models` 返回的是
`Application Support/PlanPilot/models` 下的运行副本。当前服务接受该请求，但配置与
服务公布的模型 ID 不一致，存在更换推理服务或升级后失效的风险。

### 2.2 运行指标

审计时 `/health/ai` 返回：

- 本地模型：10 次请求，8 成功、2 失败，平均约 17.0 秒；
- Flash：2 次回退，2 次成功，平均约 147.8 秒；
- Pro：当前进程尚无调用记录。

历史独立评测中 Flash 平均约 2 秒，本地产品约束评测平均约 4.36 秒。真实运行指标与
独立评测差距明显，说明问题不只是模型本身，还涉及真实 prompt 长度、并发竞争、失败
等待和回退链路。

### 2.3 测试

- 模型路由、质量约束、知识处理专项测试：20/20 通过；
- 后端非集成测试：81/81 通过；
- 测试覆盖了“异常时回退”，但尚未覆盖空输出、无效 JSON、超时预算、并发竞争和
  Embedding 旧路径。

## 3. 风险清单

### P0：任务知识匹配调用了错误的 Embedding 服务

`src/api/agent.py::_get_embedding()` 直接使用 DeepSeek 地址和 Key，并把模型写死为
`text-embedding-3-small`。DeepSeek 实际返回 404，异常随后被静默吞掉并返回 `None`。

影响：

- 部分任务与知识资料的自动关联无法使用语义匹配；
- 用户看不到错误，系统悄悄退化；
- 已经正常工作的独立 Qwen3 Embedding 配置没有被复用。

建议：删除该独立实现，统一复用知识库 Embedding 服务，并校验 1024 维结果。

### P0：Flash、Pro 和在线 Embedding 没有统一超时预算

只有本地生成模型配置了 30 秒超时和 `max_retries=0`。Flash、Pro、知识搜索和 Celery
Embedding 客户端均依赖 SDK 默认超时／重试。

影响：

- 单次用户请求可能等待数分钟；
- 本地失败后再叠加云端默认重试，尾延迟不可控；
- Celery worker 可能长期占用；
- 当前 Flash 真实平均 147.8 秒与此风险一致。

建议：分别配置连接、读取和总超时，并显式设置重试次数；为整条调用链设置总时间预算，
而不是让每一层独立等待。

### P1：自动回退只识别异常，不识别“质量失败”

LangChain `with_fallbacks()` 只能在本地请求抛异常时切换 Flash。以下情况会被当成成功：

- 空正文；
- 截断 JSON；
- JSON 结构不满足业务契约；
- 工具调用缺失；
- 输出虽可解析但关键列表为空。

解析和校验发生在路由调用之后，因此宏观计划、验收出题等入口不会因无效输出自动调用
Flash，而是返回 502、空列表或静默降级。

建议：建立“调用 → 解析 → 契约校验 → 失败后换模型”的任务级执行器。

### P1：本地模型缺少并发控制

API、Celery worker（当前并发 2）和定时任务共享同一个本地 MLX 服务，但应用没有
信号量、队列长度或背压策略。多个长 prompt 同时进入本地服务时，可能导致推理排队、
超时，随后又并发回退到 Flash。

建议：本地生成请求设置全局并发 1；短请求可排队，超过短队列／等待预算后直接走
Flash。Embedding 服务单独控制并发，不与生成模型共用限制。

### P1：熔断器与指标只存在于单进程内

- API 多 worker、Celery worker 和 beat 各自拥有独立熔断状态；
- 进程重启后指标清零；
- 只有平均延迟，没有 P50／P95、首 token、回退原因、任务类型；
- 每日任务接口在循环开始前只构建一次候选路由，即使处理中途熔断，本次循环的后续目标
  仍会继续尝试本地模型。

建议：短期先补任务类型、路由、失败原因和总耗时日志；后续把指标与熔断状态迁移到
Redis 或监控系统。

### P1：健康检查只能证明端口可访问

`/health/ai` 对本地服务只请求 `/models`，没有确认：

- 配置模型名是否存在；
- 模型能否返回非空正文；
- 首 token／完整生成延迟；
- Embedding 模型、维度和延迟；
- Flash／Pro 是否可调用。

建议：健康接口区分 `configured`、`reachable`、`ready`，深度探测另设受保护的运维接口，
避免普通健康检查产生 API 费用。

### P2：启动热身与开关不完全一致

启动热身只判断 `OPENAI_BASE_URL`，未判断 `LOCAL_MODEL_ENABLED`；热身请求也没有带正常
路由使用的 `enable_thinking=false` 参数，只验证请求不抛异常，不验证非空内容。

建议：热身复用与业务调用相同的本地客户端配置，并明确记录模型 ID、耗时和正文是否
非空。

### P2：配置默认值与文档存在旧内容

- `config.py` 默认 `MODEL_NAME` 仍为 `deepseek-chat`；
- 环境搭建指南仍描述生成端点兼做 Embedding；
- 部分技术文档仍把旧 DeepSeek 模型写成当前路由；
- `.env` 模型名与服务 `/models` 返回 ID 不一致。

建议：以“本地生成、独立 Qwen Embedding、Flash 回退、Pro 高价值判断”为唯一现行
架构，更新示例配置和文档。

## 4. 建议修复顺序

1. **统一 Embedding 调用**：移除 DeepSeek 404 旧路径，补专项测试；
2. **统一调用策略**：为 Local／Flash／Pro／Embedding 增加明确超时与重试配置；
3. **质量感知回退**：先覆盖宏观计划、每日任务、验收出题三个结构化高频入口；
4. **本地并发与背压**：生成并发限制为 1，记录排队时间和回退原因；
5. **改造健康与指标**：增加任务类型、P50／P95、空输出、解析失败和实际回退统计；
6. **配置与文档收口**：修正模型 ID、默认值、环境示例和旧架构描述；
7. **真实验收**：分别测试短聊天、宏观计划、多目标每日任务、Pro 评分、语义检索和
   本地服务中断场景。

## 5. 阶段结论

当前模型功能不是“完全不可用”，而是存在明显的可靠性和尾延迟缺口：

- Qwen3 Embedding 主链路正常；
- 本地 Qwen3.5 生成与 DeepSeek 路由可以工作；
- 但有一条确定失效且静默的 Embedding 旧路径；
- 云端调用缺少超时边界；
- 本地失败、结构化质量失败和并发竞争尚未形成完整的工程闭环。

因此不建议立刻进行微调。应先完成上述 P0/P1 工程修复，获得可信的失败类型和真实延迟
数据，再判断哪些问题确实需要通过微调解决。

## 6. 修复进展

本报告形成后已启动第一轮修复：

- 任务知识匹配改为复用独立 Qwen3 Embedding，删除 DeepSeek 404 旧路径；
- Local／云端日常模型／云端高质量模型／Embedding 增加显式超时与重试配置；
- 本地生成默认并发为 1，排队超过 2 秒触发云端回退；
- 宏观计划、每日任务和普通验收出题增加 JSON 质量校验及云端重试；
- `/health/ai` 增加 Embedding 状态、服务公布模型和模型 ID 一致性信息；
- 新增模型供应商切换脚本，DeepSeek 降级为可选预设。

### 修复后验证

- Ruff：通过；
- 后端非集成测试：87/87 通过；
- 真实集成测试：67/67 通过，总耗时 214.48 秒；
- 真实任务知识匹配：Qwen3 Embedding 返回 1024 维向量，约 0.24 秒；
- `/health/ai`：可同时报告生成服务、Embedding 服务、公布模型 ID 和质量失败次数；
- 配置查看：API Key 仅显示脱敏片段。

宏观计划仍是集成测试中最慢的单项，后续应继续记录任务级耗时与首 token 时间，再决定
是否把长宏观计划固定路由到特定云端模型，或为本地模型提供更短的计划草案契约。
