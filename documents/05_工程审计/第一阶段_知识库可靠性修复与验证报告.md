# PlanPilot 第一阶段：知识库可靠性修复与验证报告

**审计与实施日期**：2026-07-25  
**核心实施提交**：`57663ea feat: harden knowledge processing lifecycle`  
**报告状态**：第一阶段完成，可进入第二阶段

## 1. 第一阶段目标

本阶段不扩展知识检索能力，优先解决“上传成功但 AI 实际没有读到资料”的可信度问题，建立可观察、可失败、可重试的知识处理生命周期。

范围包括：

- 上传与 URL 导入状态管理
- Celery 解析、向量化和失败重试
- 文件安全校验
- 用户数据与关联对象权限校验
- 前端处理状态和错误反馈
- 迁移、测试、构建及代码质量基线

文档分块与分块级向量检索明确留到第二阶段。

## 2. 审计发现

| 级别 | 问题 | 原有影响 |
|---|---|---|
| P0 | Embedding 异常被吞掉 | Celery 把失败任务记为成功，三次重试不生效 |
| P0 | `KnowledgeItem` 没有处理状态 | 无法区分排队、解析、索引成功和失败 |
| P0 | 上传没有大小、类型和基础签名限制 | 超大或伪造文件可能消耗 API 内存和磁盘 |
| P0 | 目标、任务、笔记关联校验不完整 | 可能产生越权关联或数据库 500 |
| P1 | PDF、DOCX、XLSX 解析位于 API 请求内 | 大文件上传阻塞请求 |
| P1 | 解析异常静默返回空内容 | 用户看到成功，但 AI 无可用正文 |
| P1 | URL 抓取在请求内且未保留失败状态 | 请求慢，失败后无法重试 |
| P1 | 前端没有处理状态和失败原因 | 界面无法反映资料是否可用于 AI |
| P1 | 附件链接不携带 Bearer Token | 受保护附件无法正常打开 |
| P1 | Celery 复用异步数据库连接池 | 跨事件循环出现 `Future attached to a different loop` |

## 3. 已实施修复

### 3.1 数据与迁移

新增迁移：

`backend/alembic/versions/h2i3j4k5l6m7_add_knowledge_processing_status.py`

新增字段：

- `processing_status`
- `processing_error`
- `retry_count`
- `processed_at`
- `content_length`

状态流转：

```text
queued → parsing → embedding → ready
                    └────────→ failed → 手动重试
```

图片附件不参与语义索引，上传后直接进入 `ready`。

### 3.2 后端处理流程

- 文件上传请求只负责校验、保存和创建排队记录。
- 文件解析、URL 抓取和 Embedding 全部交由 Celery。
- 所有 Embedding 客户端失败后抛出异常，触发 Celery 重试。
- 三次重试耗尽后记录 `failed` 和简化错误信息。
- 新增 `POST /api/v1/knowledge/{item_id}/retry`。
- 搜索只读取 `ready` 状态资料。
- Celery 知识处理任务使用短生命周期异步数据库引擎，避免跨事件循环复用连接。

### 3.3 上传安全与权限

- 单文件最大 20 MB。
- 允许知识文档：PDF、TXT、MD、DOCX、CSV、XLSX。
- 允许笔记附件：PNG、JPG/JPEG、GIF、WEBP。
- 校验扩展名、MIME、PDF/Office 基础文件签名和空文件。
- 校验知识库、目标、任务、笔记均属于当前用户。
- 当前数据模型仅支持一个文件关联一个目标，前后端均按单选处理。

### 3.4 前端体验

- 展示等待、解析、索引、可用、失败状态。
- 对处理中项目每三秒刷新一次。
- 失败项目展示错误信息和重试入口。
- 上传、URL 导入、删除失败不再伪装成功。
- 附件通过带认证的 Fetch 获取 Blob 后打开。

### 3.5 工程基线

- 新增 `backend/pyproject.toml`，固定 Ruff 版本无关的项目规则。
- `.env` 保持忽略；`.env.example` 提供 `sk-xxxxxx` 等脱敏占位符。
- 日常模型与高质量模型分层：
  - `SMART_MODEL_NAME=deepseek-v4-flash`
  - `SMART_PRO_MODEL_NAME=deepseek-v4-pro`
- 普通规划、任务生成和验收出题使用 Flash。
- 重规划和验收评分使用 Pro。

  不再因后台连接线程而停在退出阶段。

## 5. 新增和调整的测试

- 上传 TXT 后返回 `queued`。
- 拒绝不支持格式和空文件。
- 拒绝无效目标和多目标关联。
- 失败文件可以重置为 `queued` 并重新派发。
- 搜索仅使用 `ready` 内容。
- 文本提取成功、空文本失败、非索引附件跳过。
- 集成测试显式区分上传入队和处理完成。
- 测试环境模拟 Redis 黑名单和 Celery 派发，避免外部状态干扰单元测试。
- 模型路由测试确认普通验收使用 Flash，重规划和验收评分使用 Pro。
- 审核失败返回复习建议；仅 60～79 分的通过结果返回深化追问。

## 6. 遗留项

这些事项不阻塞第二阶段：

1. 长文档目前仍只保存一条文档记录和一个向量。
2. Embedding 输入仍只使用标题和正文前 8,000 字符。
3. 富文本内嵌图片刷新后的持久化鉴权尚需专门资源模型。
4. 其他旧 Celery 定时任务仍应逐步迁移到短生命周期异步数据库连接。
5. 应为所有外部 LLM 请求建立统一超时、重试和调用指标。
