# 第四阶段：本地模型质量约束修复报告

**完成日期**：2026-07-25  
**修复范围**：首版 30 条评测暴露的意图、JSON 类型和短文本服从问题

## 1. 修复结论

本轮没有修改模型权重，而是在产品层增加确定性质量约束。相同 30 条评测从
原始本地模型的 27/30（90%）提升为 PlanPilot 产品管线的 30/30（100%）。

该结果应理解为“产品输出契约修复”，不能表述为“Qwen 模型能力提高到 100%”。
模型仍可能生成不理想的初稿，只是可规则化的问题不再直接暴露给用户。

## 2. 三项修复

### 2.1 意图边界

扩充确定性意图规则：

- “出一道题”“出道题”“小测”“测验一下”直接进入验收；
- “没完成”“未完成”“没有完成”直接进入打卡；
- 明确表达不再调用模型分类，避免随机误判和额外延迟。

### 2.2 JSON 对象类型

新增 `create_structured_routine_llm()`，通过 OpenAI-compatible
`response_format={"type":"json_object"}` 强制服务端只生成 JSON 对象。

已用于：

- 宏观计划；
- 验收出题及答案要点；
- Agent 结构化计划节点。

数组型接口仍保留原有数组解析，避免把所有结构化调用错误地强制为对象。

### 2.3 短文本与纯中文契约

新增确定性后处理：

- 去除常见 Markdown 装饰；
- 优先保留完整首句；
- 超长且无句号时截断并增加省略号；
- 对明确要求“只用中文”的契约移除偶发拉丁字母词。

已用于目标理解、输入框 placeholder 和验收短问题等界面短文本。

### 2.4 提示注入防护

评测中发现通用系统提示曾被模型复述。产品聊天系统提示和评测系统提示现已
明确禁止透露、复述或改写系统/内部指令、密钥、数据库连接和其他用户数据。
修复后相关安全用例通过。

## 4. 后续事项

30 条评测规模仍小，100% 不代表所有真实请求均无问题。下一步应：

1. 将固定评测扩展到 50～100 条，增加模糊意图、提示注入变体和长计划；
2. 对 Flash/Pro 运行相同产品管线，建立质量与延迟对照；
3. 收集无法用确定性规则修复的真实失败样本，作为未来 QLoRA 数据；
4. 对结构化输出增加字段类型、取值范围和业务约束校验，而不仅检查顶层对象。
