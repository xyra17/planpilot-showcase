# 第三阶段：本地推理服务工程化与评测报告

**完成日期**：2026-07-25  
**对应模型**：Qwen3.5-9B-MLX-4bit  
**阶段结论**：本地生成模型已具备后台托管、健康检查、故障回退、熔断和首版
固定评测能力；可以进入质量优化与数据闭环阶段。

## 1. 本阶段完成内容

### 1.1 后台服务

- 新增 macOS launchd 安装、运行和卸载脚本；
- 服务标签：`com.planpilot.llm`；
- 登录后自动启动，异常退出后自动恢复；
- 标准输出和错误日志写入 `~/Library/Logs/PlanPilot/`；
- 由于 launchd 无法读取 Desktop/Downloads，使用 APFS 写时复制在
  `~/Library/Application Support/PlanPilot/models/` 建立运行副本；
- Downloads 中的原模型没有移动或删除。

验证时 `launchctl` 状态为 `running`，`/v1/models` 返回模型信息。

### 1.2 可观测性和故障处理

新增 `/health/ai`，返回：

- 本地服务是否可达；
- Flash、Pro 是否已配置；
- 本地熔断状态和剩余冷却时间；
- local、flash、pro 各自请求数、成功数、失败数和平均耗时。

指标只记录路由、结果和耗时，不记录 prompt、response、API Key 或用户文档。

默认连续两次本地调用失败后熔断 60 秒。熔断期间日常请求直接选择 Flash；
冷却结束后放行一次本地探测请求，成功则恢复。

真实故障测试中，将本地端点临时指向不可达端口，结果为：

- 本地失败检测约 20 ms；
- 自动 Flash 回退成功，约 932 ms；
- 用户获得正常响应；
- 熔断状态正确变为 `open`。

测试结束后临时配置和熔断状态均已恢复。

## 2. 首版本地模型评测

固定评测集位于 `backend/evals/llm_baseline_v1.json`，共 30 条，不含真实用户
数据，覆盖四类场景：

| 类别 | 数量 | 通过 |
|---|---:|---:|
| 意图识别 | 8 | 7 |
| JSON 结构 | 8 | 7 |
| 指令遵循 | 7 | 6 |
| 安全边界 | 7 | 7 |
| 合计 | 30 | 27 |

总体规则通过率为 **90%**，平均响应耗时为 **5.965 秒**。详细机器可读报告：
`backend/evals/reports/local_qwen35_baseline_2026-07-25.json`。

三个失败样例：

1. “出一道题考考我”被误判为 `goal_setup`；
2. 要求输出单个 JSON 对象时返回了对象数组；
3. 要求只用中文简答时输出了过长的结构化说明。

这说明本地模型的主要问题不是基础安全性，而是意图边界和严格格式/长度服从。
这三类样例应优先进入 Prompt 优化和未来训练数据，不需要因此把日常流量退回
云端模型。

## 3. 验证结果

- 本地固定评测：30 条，27 条通过；
- 真实本地故障 → Flash 回退：通过；
- launchd 后台启动、强制重启恢复与 `/v1/models`：通过（重启约 2 秒恢复）；
- 路由、熔断、指标、健康接口专项测试：通过；
- 后端全量测试：`127 passed`，耗时 5 分 17 秒；
- Ruff 和 Git whitespace 检查：通过。

## 4. 已知限制

- 指标保存在 API 进程内，进程重启后归零，尚未接 Prometheus 或持久数据库；
- 当前只统计平均耗时，尚未统计 P50/P95 和首 token；
- 熔断状态不在多个 API worker 间共享；
- 首版评测是规则评测，尚未加入人工偏好评分；
- APFS 克隆逻辑大小约 5.6 GB，初始共享原文件数据块；后续模型文件被修改时
  才可能逐步增加物理占用。

## 5. 下一步

2. 增加首 token、P50/P95、回退率和不同请求类型指标；
3. 对同一评测集运行 Flash/Pro，形成质量、延迟、费用三方基线；
4. 收集经同意和脱敏的真实失败样本，建立训练集与独立验证集；
5. 数据达到首轮标准后，再进行 10～20 条样例的 QLoRA 兼容性试验。
