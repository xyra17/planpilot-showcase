## 1. 数据审计

原文件从 `/Users/Admin/backend/evals/` 移入项目。结构审计结果：

- 总数 40；
- intent、structured、instruction、safety 各 10 条；
- 40 个 ID 全部唯一；
- 无重复 prompt；
- JSON、正则和验证器结构合法；
- 未发现 API Key、联系方式或真实用户数据。

语义审计发现并修复：

1. 一条打卡样例同时要求“跳过任务”，存在打卡/重规划双重意图；
2. “最佳晨间时段”标准答案主观；
3. 二元交叉熵缩写的题面写 4 个字母，正则却实际要求 5 个；
4. 一个 JSON 用例声称字段顺序可变，正则却固定字段顺序；
5. 两个长 JSON 用例没有限制列表长度，导致合理回答超时或截断；
6. 多个安全验证词过宽，可能把包含“API”“用户”等词的违规回答误判通过；
7. 部分合规拒绝措辞未被验证器覆盖，造成假阴性。

修订后的数据集用于最终评测。生成数据不能未经审计直接成为标准答案，本次结果
也证明自动结构检查无法替代语义检查。

## 2. 产品代码改进

新数据额外暴露并修复了以下产品问题：

- 意图规则增加“换成、改成、只背了、只读了、记录一下、出几道题、怎么开始”
  等自然表达；
- 意图模型 token 上限从 10 提升到 100，避免 Flash 推理耗尽后正文为空；
- 聊天空回复增加用户可见的安全兜底，不再让前端显示空消息；
- 系统安全策略增加数据库、后台数据、其他用户信息、作弊、结果保证，以及严重
  压缩睡眠和突然高强度运动等场景；
- 评测器按生产意图提示运行，结构化和安全用例使用合理的 token 上限；
- “只用中文”约束由内容规则统一处理，不再绑定旧用例 ID。

## 4. 结论

当前固定评测总量已由 30 条扩展为 70 条。新 40 条数据在审计后有价值，尤其
帮助发现了 Flash 空正文、自然意图边界和极端健康计划安全问题。

现有架构决策仍然成立：

- 日常请求：本地 Qwen 优先；
- 本地故障或超时：Flash 回退；
- 复杂重规划和最终审核：Pro；
- 硬格式、安全和空响应：由产品代码兜底，不能只依赖模型。

代码验证结果：

- 后端全量测试：`136 passed`，耗时 4 分 44 秒；
- Ruff：通过；
- 临时评测服务已停止，`com.planpilot.llm` launchd 服务已恢复；
- 恢复后的本地模型实际请求通过。
