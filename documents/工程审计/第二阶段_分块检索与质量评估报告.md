## 3. 分块与批量向量化

默认参数：

- 目标分块长度：1,200 字符
- 相邻重叠：200 字符
- Embedding 批大小：32
- 最大提取正文：沿用第一阶段的 50,000 字符限制

分块优先在段落、换行或句子边界结束，同时记录原文字符范围。文档重新处理前会删除旧分块，避免重复索引。

Embedding 返回数量和向量维度均会校验。任一批次失败时继续尝试下一个兼容服务；所有服务失败后沿用第一阶段的 Celery 重试和失败可见机制。

原 `knowledge_items.embedding` 暂时保留第一段向量，用于兼容旧代码和滚动升级；新搜索优先使用 `knowledge_chunks`。

## 4. 检索与引用

检索顺序：

1. 分块级余弦向量检索
2. 未重建旧资料的整文档向量检索
3. 分块级关键词检索
4. 旧资料整文档关键词检索

向量最低相关度仍为 0.3。搜索继续执行用户所有权和可选目标过滤。

搜索结果新增：

- `source_type`
- `source_url`
- `chunk_index`
- `start_char`
- `end_char`
- `citation`，例如 `CPA讲义.pdf · 第 3 段`

旧调用方原有的 `id`、`title`、`snippet`、`score`、`goal_id` 和
`kb_id` 均保持兼容。

## 5. 旧资料重建

新增：

`POST /api/v1/knowledge/reindex?limit=100`

接口只处理当前用户、状态为 `ready`、来源为上传或 URL、且尚无分块的资料。
每批最多 500 项，任务进入现有 Celery 队列；已分块资料不会重复派发。

## 6. 检索质量评估

新增：

`POST /api/v1/knowledge/search/evaluate`

请求示例：

```json
{
  "cases": [
    {
      "query": "资产负债表的确认条件",
      "expected_item_ids": ["知识文档 ID"]
    }
  ],
  "limit": 5,
  "goal_id": null
}
```

输出：

- 每个问题的召回文档顺序
- 单问题 Recall@K
- 单问题 Reciprocal Rank
- 数据集平均 Recall@K
- Mean Reciprocal Rank（MRR）

该接口只在当前用户资料内检索，不暴露其他用户文档。
