## 已验证的链路

- 目标契约：baseline、success criteria、must-cover、may-skip、课程约束和暂定考试日期。
- 资料治理：6 份资料建立 URL 来源，AI 候选进入 draft，用户确认后才写入 `source_role`、`source_metadata` 和 `processing_policy`。
- 知识地图：语义模型可用时返回带原文 quote 的候选；模型超时则返回 `structural_fallback`，界面和审计均标记降级。范围资料才可以定义地图，参考资料、笔记和证据不能静默扩大范围。
- 地图治理：逐项审核、合并、拆分、版本历史和恢复均已通过 API 跑通；恢复不会覆盖历史，而是生成新的恢复版本。
- 计划与行动：宏观计划 API 在模型网关可用时先生成草案、用户确认后激活；本次网关超时的目标保留显式 `fallback_after_model_timeout` 计划，随后仍创建带 `why_now`、步骤、资料引用、产出、验收和降级路径的今日行动。模型超时不是“成功生成计划”。
- 现实约束与偏差：写入课程/实验课时间块；英语行动完成并记录实际 61 分钟；数学因实验拖堂部分完成；六级因班会顺延，演练 preview/apply/undo/reapply。
- 反馈闭环：任务笔记关联目标和任务；每日复盘写入 typed mastery evidence；Pilo 会话引用目标、行动、资料摘要和笔记，但不会替用户自动执行。
- 影响预览：目标契约变化、资料角色变化均先返回受影响概念/任务和安全默认，未直接覆盖已激活计划。

## 成熟度边界

`semantic_distillation` 是模型对受限正文的候选归纳，不是权威事实、考试官方大纲或唯一学习顺序。每条概念必须保留正文中可定位的 quote，并经过用户审核；模型失败时只能降级为结构抽取，不能冒充语义理解。

`source_metadata` 已是后端契约，前端现在提供可编辑的资料角色、类型、权威性、难度、版本、覆盖主题、章节、允许的 AI 用途、排除项和本地/云端处理策略。变更前有 impact preview；云端处理必须由用户明确允许，默认 local-only。

掌握证据的 reliability 是产品策略权重，不是心理测量真值；长期效果仍需真实用户纵向实验。网关超时 fallback 计划证明系统可恢复，不证明模型计划质量。
