# 语义状态小组件实施报告

完成日期：2026-07-31。

## 背景

知识库处理状态、错误提示、成功提示、评分和任务类型等小组件过去直接使用固定的红、绿、黄背景。它们在默认风格中可用，但无法稳定适配暗黑、护眼和手账纸稿风格。

## 设计原则

组件只表达语义，不直接选择具体颜色：

| 语义 | 使用场景 |
|---|---|
| `neutral` | 等待、停用、普通计数 |
| `info` | AI、已接受、知识关联 |
| `progress` | 排队、处理中、模型调用 |
| `success` | 处理完成、验收通过、应用成功 |
| `warning` | 需确认、待复习、风险提示 |
| `danger` | 处理失败、请求失败、不可逆操作 |

每种界面风格独立定义上述语义的背景、文字和边框。手账风格增加虚线和不规则圆角，暗黑风格使用低亮背景和高可读前景色，护眼风格使用低饱和自然色。

## 新增基础组件

- `StatusBadge`：状态、进度、评分、数量旁的紧凑徽标。
- `InlineNotice`：错误、警告、成功和信息型行内提示。
- 统一 Toast、确认弹窗图标、危险操作按钮及紧凑行内操作样式。

## 首批改造范围

- 知识库：等待处理、排队中、解析中、建立索引、可用于 AI、处理失败和重试操作。
- 知识库：筛选标签、文件数量、知识库与目标关联、验收评分。
- 学习伙伴：Proposal 状态、数据质量、认知置信度和错误提示。
- 旧 Agent：工具运行状态、确认提示、打卡成功、学习验收和重规划结果。
- 目标：目标状态、完成比例和删除错误。
- 全局：Toast 与确认弹窗。

## 兼容策略

仍未迁移到新组件的旧页面由产品外壳中的语义色兼容层托底。后台不使用该兼容层，继续保持固定运营主题。

## 验证

- lint 与生产构建。
- 主题 E2E 验证四种界面风格拥有不同的成功与失败语义色。
- 知识库页面验证真实语义徽标已渲染。
- 浏览器检查知识库及设置页面的暗黑、护眼和手账显示。
