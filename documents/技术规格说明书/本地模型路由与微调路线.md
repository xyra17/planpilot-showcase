# PlanPilot 本地模型路由与微调路线

**更新时间**：2026-07-25  
**状态**：混合推理架构已落地；微调尚未开始

## 1. 当前决策

PlanPilot 不把“全部本地化”和“立即微调”绑定在一起。先让未经微调的本地
Qwen3.5-9B 承担高频、低风险请求，用真实运行数据验证质量和延迟；DeepSeek
继续作为质量保险。确认本地模型的具体短板后，再以 QLoRA 做针对性训练。

当前模型职责如下：

| 请求类型 | 主模型 | 失败回退/终审 |
|---|---|---|
| 意图分类、普通聊天、打卡反馈 | 本地 Qwen3.5-9B | DeepSeek V4 Flash |
| 目标理解、输入提示、笔记辅助 | 本地 Qwen3.5-9B | DeepSeek V4 Flash |
| 每日任务、复习题、验收出题 | 本地 Qwen3.5-9B | DeepSeek V4 Flash |
| 初始宏观计划草案 | 本地 Qwen3.5-9B | DeepSeek V4 Flash |
| 复杂重规划方案及执行 | DeepSeek V4 Pro | 无自动降级 |
| 学习答案的最终评分 | DeepSeek V4 Pro | 无自动降级 |
| 知识库向量化与语义检索 | 本地 Qwen3-Embedding-0.6B | 关键词检索 |

路由入口集中在 `backend/src/core/llm_router.py`。日常调用开启本地模型的
`enable_thinking=false`，避免短请求把时间和 token 消耗在推理文本上。本地
连接失败、超时或返回错误时，LangChain 自动转发给 Flash。Pro 必须显式调用，
不会被普通业务误用。

## 3. 完整演进路线

### 阶段 A：混合路由与可观测性

1. 保持当前“本地 → Flash”日常路径和“Pro 专用”路径。
2. 为每次调用记录路由、首 token、总耗时、token 数、是否回退和错误类型；
   日志中禁止记录 API Key 和完整私人学习内容。
3. 建立超时与熔断：连续失败时短期跳过本地模型，恢复后自动探测。
4. 将 MLX 服务改为受控后台服务，并增加健康检查和启动说明。

完成条件：本地服务重启可恢复，回退行为可验证，用户请求不会因本地模型退出
而长时间卡住。

### 阶段 B：评测基线

建立一套不参与训练的固定测试集，覆盖：

- 意图分类和边界表达；
- 普通学习问答与打卡反馈；
- 短期、长期、有知识库和无知识库的计划；
- 严格 JSON 输出、日期和时间预算约束；
- 恶意提示、隐私信息和越权请求；
- 本地模型、Flash、Pro 的质量、延迟和成本对照。

先从 50～100 个高价值样例开始。评分至少包括 JSON 合法率、约束满足率、
任务可执行性、事实依据、人工偏好和 P50/P95 延迟。评测集与训练集必须分离。

### 阶段 C：数据闭环

收集经用户同意且已脱敏的真实请求、模型草稿、最终采用版本和失败原因。
训练样例优先选择“本地模型失败而 Flash/Pro 成功”的差异样本。云端模型可生成
候选答案，但必须经过规则校验或人工审核，不能把未经检查的输出直接当真值。

首轮建议积累 200～500 条高质量训练样例；数量不够时宁可继续收集，也不以
大量低质量合成数据填充。

### 阶段 D：QLoRA 兼容性试验

先用 10～20 条样例和少量训练步验证当前 Qwen3.5 MLX 量化模型是否能稳定
完成 QLoRA：训练、保存 adapter、加载 adapter、推理、重启后复现。重点检查
模型架构支持、显存峰值、训练速度和输出格式。

兼容性通过后再进行正式实验；若 MLX-LM 对该架构的训练支持不足，保留 MLX
推理，改用 Hugging Face PEFT/TRL 训练 LoRA，再转换或合并为可部署格式。

### 阶段 E：正式微调和灰度发布

微调只教授稳定的行为模式，例如 PlanPilot 输出结构、任务拆分风格、追问策略
和约束遵循。最新知识、用户资料和知识库内容继续由 RAG 提供；日期分配、预算
校验等确定性逻辑继续留在代码中。

每个 adapter 使用独立版本和数据清单。只有在固定评测集上不降低安全性、
JSON 合法率和核心质量，并明显改善目标指标时才进入灰度。灰度期间保留
Flash 回退和一键关闭本地模型的配置。

### 阶段 F：逐步减少 API 依赖

根据真实指标逐项扩大本地模型范围，不按主观感受一次性切换。复杂重规划和
最终审核只有在本地模型连续达到预设质量门槛后才迁移；在此之前 Pro 是质量
保险而不是永久架构依赖。

## 4. 不应通过微调解决的问题

- 最新资料或个人文档：使用知识库检索。
- 日期、总时长、任务数量等硬约束：使用程序校验和后处理。
- 本地服务不可用：使用健康检查、熔断和 Flash 回退。
- Prompt 中可以稳定表达的格式要求：先优化 Prompt 和解析器。
- Embedding：继续使用独立的 Qwen3-Embedding 模型，不用生成模型替代。

## 5. 架构修改后的下一步

下一步不是立即跑长时间微调，而是完成“阶段 A 的可观测性和服务托管”，并
同步建立第一版固定评测集。得到本地模型对比 Flash/Pro 的失败样本后，再进行
小规模 QLoRA 兼容性试验。这样训练目标来自证据，也能判断微调是否真的改善
体验。
